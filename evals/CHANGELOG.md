# Eval baseline changelog

`evals/results/baseline.json` is the last accepted run. The regression gate (`python -m evals.regression`, docs/09 §16) compares every run with it and fails on a headline regression beyond tolerance. To accept a deliberate trade-off, replace `baseline.json` with the new run's `summary.json` in the same commit and add a line here naming its `run_id` and why. A baseline whose `run_id` is not listed here fails the gate.

- `evalrun_20261013T080503Z_2732b6c`: first accepted run (Stage 1, deterministic suites only). Numbers are as measured, including the targets missed. The working tree had uncommitted storage, API and frontend work from parallel Stage 1 tasks; none of it is imported by the eval suites.
- `evalrun_20261013T084626Z_7c25044`: forecast engine `fc-1.2.0` (calibrated uncertainty: one-offs modelled separately, every unscheduled outflow forecast, parameter uncertainty for short histories; working-day shifts; payer names without invoice numbers) and E-FC's explicit onboarding-confirmation arm. Accepted trade-off: P10–P90 coverage P2 0.098 → 0.834 and S4 0.116 → 0.712, pinball P2 £2,197 → £1,538, P1 MAE(30) £624 → £553; but P50 MAE(30) rose on P2 (£5,265 → £5,630) and S4 (£4,364 → £4,973) and is now **worse than the best naive baseline** on both (£4,877 and £4,592). P1 coverage (0.584) still misses 0.72–0.88. All of this is shown in the README, not hidden.
- Authored sets (not a baseline): the E-SEC injection sets moved into `evals/datasets/authored/` and were frozen with `python -m evals.authored --write`. The dev set grew from 20 to 27 cases after the first run: one case per weakness fixed in the guard rule pack (guard-1.1.0, guard-1.2.0), so the pack is never tuned on the test set. The untuned first-run numbers are in the E-SEC suite notes.
- Target change (not a baseline), 13 Oct 2026, owner-approved: E-FC `FC-mape` (MAPE(30) ≤ 12%) is replaced by `FC-mase` (MASE(30) < 1, P1) and `FC-mase-vs-best` (MASE(30) below the best naive baseline's, P1). MAPE divides by the balance, which is near £0 at exactly the pre-payday lows that matter, so it explodes where accuracy matters most. P1's MAE beat every naive baseline while its MAPE was 0.5. MAPE stays in the report (docs/09 §7.3–7.4). The same change brings forecast engine `fc-1.3.0`, with the ONS irregular-expense prior (docs/07 §6.2b) and band calibration (§6.8a). Both were tuned on dev origins only, and E-FC now reports dev and test separately. The next accepted run must list its run_id here as usual.
- 2026-10-13, authored sets (owner-approved): `bad_proposals.jsonl` corrected for authoring errors found by the Verifier and the engine. V-11 stays strict.
  - 23 "good" proposals claimed a category rose while citing only the baseline forecast; the judge rightly failed V-11. Where the real trend detector finds that rise on the persona's ledger (P1 eating out GP-008…012, taxis GP-017…020), the `fnd:category_spike:<category>` ref is added and resolves; where no finding exists (P1 clothing GP-013…016, P1 general shopping GP-021…024, P2 shopping GP-033…037, P2 Spotify GP-038), the rationale is reworded to the forecast-supported claim instead of inventing evidence. The resolvable `fnd:` set now includes the detector's category spikes (README).
  - GP-039, GP-040 (P2 ISA sweep moved within the same pay cycle) relabelled `REJECT`, defect `immaterial_timing` (V-05): the engine shows no reduction in the chance of going below the buffer. Set now 62 `REJECT` + 38 `APPROVE`. Re-frozen with `python -m evals.authored --write`.

- `evalrun_20261013T144947Z_fa7026d` (13 Oct 2026): Stage 2 baseline. Forecast engine `fc-1.3.0` (self-calibrating band, ONS irregular-expense prior); agent suites added from committed Mesh recordings (E-SCN, E-VER, E-GRD, E-SEC, E-CTX, E-UI). Gates now count every measured target, not only Stage 1 ones, so E-CAT (hybrid 0.916 vs 0.93), E-CTX (follow-ups), E-SEC (SEC-1, one chat attack reaches the specialists) and E-UI (block selection) fail and are listed as shortfalls. Accepted regression-gate movement: P2 P10–P90 coverage 0.834 → 0.873, still inside 0.72–0.88, from the deliberate calibration change. E-ORC and E-AUD are not built yet.
